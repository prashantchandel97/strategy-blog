TWEET OPTIONS

[A] The Number

33,000 tokens: that's how much Claude Code burns on system scaffolding before reading your prompt. OpenCode burns 7,000. Add production setup (instruction files, servers, subagents) and you hit 75k-85k tokens before the user types a single word.

[B] Counter-Narrative

Claude Code's richer scaffolding looked like an advantage: better tool orchestration, more structured prompts. Then Systima ran it on a newer model. Same task, twice the requests, 298k tokens vs OpenCode's 133k. The architectural edge flipped to a fixed liability.

(263 chars)

[C] The Number (cache angle)

Claude Code wrote 54x more cache tokens than OpenCode on identical workloads. Not because the task was harder: because it rewrites tens of thousands of prompt-cache tokens mid-session. Your cost spikes aren't task complexity. They're caching thrash.

(261 chars)

[D] Counter-Narrative (incentive misalignment)

Anthropic's incentive: sell more tokens (higher preamble equals higher revenue). Your incentive: burn fewer tokens, spend context on the actual task. That misalignment sharpens as enterprises scale agents. By 2027, the token-cost delta makes Claude's pricing untenable.

(279 chars)

[E] The Number (production scale)

7,000 vs 33,000 tokens of preamble. 2.5x gap that widens at production scale. A 72KB instruction file adds 20k tokens. Five MCP servers add 7k more. OpenCode climbs to 35k baseline. Claude Code? Already at 85k before you type. The gap compounds, not closes.
